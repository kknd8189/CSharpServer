# AI 활용 방식 — Claude Code 로 관측 계층을 만든 기록

> 이 프로젝트의 관측 계층(메트릭·로그·검증)은 Claude Code 와 함께 만들었다.
> 숨길 이유가 없다고 판단해 **어떻게 썼고, 무엇이 되고 무엇이 안 됐는지**를 남긴다.
> 도구를 썼다는 사실보다 **어떤 규율로 썼는지**가 결과를 갈랐다.

---

## 1. 작업 루프

```
   사람: 목표·방향 결정            "메트릭은 프로메테우스로 분리하자"
     ↓
   AI:  코드베이스 조사 → 설계안 제시
     ↓
   사람: 승인 / 방향 수정
     ↓
   AI:  구현 → 빌드 → 테스트
     ↓
   AI:  ★ 실측 검증 (여기가 핵심)
     ↓
   AI:  검증에서 나온 발견을 보고 ──→ 다시 사람의 판단으로
```

**★ 표시한 단계가 이 프로젝트에서 실제 가치를 만든 지점이다.**
"빌드가 통과했다"는 아무것도 보장하지 않는다. 다음을 매번 확인하고 넘어갔다.

- 컨테이너를 재빌드해 띄우고
- 부하 클라이언트나 치터 시뮬레이터를 실제로 붙이고
- Prometheus / Elasticsearch 를 **쿼리해서** 값이 들어왔는지 보고
- 필드 타입까지 확인 (`long` 인지 `double` 인지, `keyword` 인지)

이 규율이 없었으면 아래 목록의 버그는 하나도 못 찾았을 것이다.

---

## 2. 이 방식으로 드러난 버그들

관측을 붙이는 작업이었는데, **관측을 붙이자 잠들어 있던 문제들이 드러났다.**
대부분 오래 있었지만 아무도 볼 수 없던 것들이다.

| # | 버그 | 어떻게 드러났나 |
|---|---|---|
| 1 | **컨테이너에서 파일 로깅이 아예 안 되고 있었음** | 볼륨이 root 소유인데 서버는 비루트(uid 1654). Serilog 파일 싱크는 실패해도 예외를 안 던져 콘솔만 정상이고 파일은 조용히 비어 있었다 |
| 2 | `Listener` 의 `ObjectDisposedException` | 로깅을 켜자 그동안 `Console.WriteLine(e)` 로 삼켜지던 예외가 보였다. 조작 패킷이 올 때만 터지던 경로 |
| 3 | **DummyClient 이동의 절반이 버려지고 있었음** | 맵은 단일 Y 평면인데 더미가 Up/Down 으로 PosY 를 움직였다. 서버가 100% 거부 → 부하 테스트가 절반짜리였다 |
| 4 | DummyClient 가 서버 보정을 무시 | `S_MoveHandler` 가 빈 껍데기. 좌표가 갈라져 정상 더미 292 세션이 어뷰저로 킥됨 |
| 5 | 사망 리스폰 in-flight 오탐 | 서버가 스스로 옮긴 직후의 이동을 어뷰징으로 셌다. 800 CCU 에서 360 건 |
| 6 | **유예가 텔레포트 핵을 통과시킴** | 5번을 시간만으로 유예했더니 치터 시뮬레이터의 50 칸 점프가 전부 통과. 좌표 조건을 추가해 막음 |
| 7 | **플레이어 Auto 스킬이 no-op** | `// hit 처리 자리` 로 비어 있었다. 플레이어가 몬스터를 죽일 수 없어 드랍/보상 경로가 통째로 잠들어 있었다 |
| 8 | DummyClient 스킬이 100% 거부됨 | 매번 `State=Moving` 만 보내 서버의 `State==Idle` 게이트에 걸렸다 |
| 9 | **드랍 확률이 의도의 2배** | `Next(0,101)` + `rand <= sum`. 경우의 수 101 개 vs 100 분율. `probability=1` → 실제 1.98% |
| 10 | ES 매핑 충돌 / 타입 오추론 | `service` 를 문자열로 넣어 ECS 객체 매핑과 충돌(전 이벤트 드롭). `PacketsRecvPerSec` 이 첫 값 0 때문에 `long` 으로 굳어 소수점 절삭 |
| 11 | 핑 잡이 세션 종료 후에도 예약됨 | 죽은 세션에 30 초 뒤 "Ping timeout" 경고를 남기고 있었다 |

**7·8·9 는 서로 물려 있었다.** 드랍 로그를 붙였는데 0 건이 나와서 파고들었더니
플레이어가 몬스터를 죽일 수 없었고(7), 더미는 스킬을 쏘지도 못했고(8),
고치고 나서 확률을 재보니 계산이 틀려 있었다(9).
**관측을 붙이지 않았으면 셋 다 계속 묻혀 있었을 것이다.**

## 3. 측정이 정직해진 결과

부하 테스트 수치가 두 번 바뀌었다. 성능이 변한 게 아니라 **측정이 고쳐진 것**이다.

| 시점 | 주장 | 실제 |
|---|---|---|
| 처음 | "1000 CCU" | Debug 빌드, 근거 불명확 |
| 1차 측정 | 400 CCU (틱 **최댓값** 기준) | 5 초에 149 틱 중 1 틱만 튀어도 걸림 — 과도하게 보수적 |
| 2차 측정 | **500 CCU** (**p99 · 예산 초과율** 기준) | 히스토그램 도입 + 더미 버그 수정 후 |

같은 CCU 에서 서버가 하는 일이 **최대 3.9 배** 늘었다(더미가 유효한 이동을 보내게 된 뒤).
즉 예전의 "1000 CCU" 는 지금 기준으로 500 명분의 일도 안 하고 있었다.

> 숫자가 내려갔지만, **왜 내려갔는지 설명할 수 있는 숫자**가 됐다.

## 4. AI 가 잘한 것 / 사람이 해야 했던 것

### AI 쪽이 확실히 빨랐던 작업

- **치터 시뮬레이터 작성** — PacketGenerator 의 바이너리 포맷(헤더 4바이트, 중첩 객체
  존재 플래그, 문자열 u16 길이)을 `Protocol.cs` 에서 읽어 Node 로 직접 조립.
  텔레포트/스피드핵/스킬연타 3 종을 즉석에서 만들어 검증에 썼다
- **부하 결과 집계** — Prometheus `query_range` 를 긁어 CCU 버킷별로 p50/p95/p99 와
  예산 초과율을 계산하는 스크립트
- **대시보드를 코드로** — Grafana 프로비저닝 파일, Kibana saved objects API 호출
- **반복 검증** — 빌드 → 컨테이너 재기동 → 부하 → 쿼리 확인의 사이클을 지치지 않고 반복

### 사람이 결정해야 했던 것

- **방향** — "메트릭을 프로메테우스로 분리할까", "패킷 로그를 ES 에 남길까",
  "실무와 비슷한 구조로 가자". 여기서 나온 판단이 나머지를 규정했다
- **트레이드오프 승인** — 어뷰징 임계값, 유예 창 길이, 로그 보존 기간
- **범위 제한** — 가챠 시스템처럼 패킷 스키마가 필요한 작업은 하지 않기로

### AI 가 못 한 것 (구조적 제약)

- **패킷 스키마** — 정의가 Google Sheets 에 있고 로컬에 원본이 없다.
  `Protocol.cs` 는 PacketGenerator 로 재생성해야 하므로 사람이 먼저 시트를 고쳐야 한다.
  가챠 기능을 이번에 넣지 않은 이유
- **첫 판단이 틀린 경우가 있었다** — 리스폰 유예를 "시간만" 으로 잡은 게 대표적이다.
  치터 시뮬레이터로 재검증하지 않았으면 **보안 구멍을 만든 채로 끝났을 것**이다.
  AI 의 설계를 그대로 믿지 않고 반증을 시도한 게 막았다

## 5. 배운 것

**1. "빌드 통과" 와 "동작 확인" 은 완전히 다른 일이다.**
이번에 찾은 버그 11 개 중 컴파일 에러였던 건 하나도 없다.

**2. AI 에게 검증까지 시켜야 한다.**
"구현해줘" 로 끝내면 위 목록은 안 나온다. "구현하고, 띄우고, 쿼리해서 값이
들어왔는지 확인하고, 안 맞으면 원인을 찾아라" 까지가 한 작업이다.

**3. AI 의 산출물도 반증 대상이다.**
6 번(유예가 핵을 통과시킴)은 AI 가 만든 설계를 AI 가 만든 시뮬레이터로 때려서 나왔다.
"만든 사람이 검증하면 안 된다" 는 원칙은 AI 에게도 적용되지만,
**반증 도구를 싸게 만들 수 있다는 점**이 오히려 이 방식의 강점이다.

**4. 관측은 기능이 아니라 렌즈다.**
관측 계층을 만드는 작업이었는데 결과적으로 게임 로직 버그(7·9)를 더 많이 고쳤다.
안 보이던 것이 보이기 시작하면 그때부터 진짜 문제가 드러난다.
